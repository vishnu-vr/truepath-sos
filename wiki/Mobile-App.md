# Mobile app (TruePath Care)

Flutter app in `app/`, package `app.truepath.truepath_care`, Android-first.
Backend base URL: `app/lib/config.dart` (10.0.2.2 = host Mac from the
Android emulator).

## Files

| File | Role |
| ---- | ---- |
| `lib/main.dart` | Firebase init, FCM background handler, `AuthGate` (auth stream → AuthScreen/HomeScreen), `markAlertResolved()` |
| `lib/config.dart` | backend base URL |
| `lib/api.dart` | `backend(path, body)` — authenticated POST, throws `BackendException` with the server's message |
| `lib/alarm.dart` | `SosAlarm`: the SOS alarm notification (full-screen intent, alarm audio stream + alarm sound, `FLAG_INSISTENT` loop, ongoing, 15 min timeout, own group per alert), `stop()` → quiet "handled by …" note, stale (>30 min) pushes shown as a plain notification, native channel `truepath/alarm` helpers. Runs in the FCM background isolate too |
| `lib/push_service.dart` | notification permission, token registration (`/registerToken`), foreground pushes → `SosAlarm.handleData` + open alarm screen, notification taps / "I'm on it" action / cold-start launch details |
| `lib/screens/alarm_screen.dart` | full-screen red alarm with I'M ON IT (→ `/ack`) and Open in Maps; hands over to the SOS screen as soon as anyone responds |
| `lib/screens/alarm_setup_screen.dart` | `AlarmSetupBanner` (Alerts tab, shown while something required is off) + `AlarmSetupScreen` checklist: notifications, full-screen permission, battery optimisation, DND access (optional), OEM autostart hint, "Test the alarm" |
| `lib/screens/auth_screen.dart` | sign in / create account (creates `users/{uid}` doc) |
| `lib/screens/home_screen.dart` | tabs: Alerts (active + history, live query on `memberUids`) and My canes (two queries: caregiver-of, cane-user-of); FAB → ClaimScreen |
| `lib/screens/claim_screen.dart` | QR scan (mobile_scanner) or manual claim-code entry → `/claim` |
| `lib/widgets/live_location_card.dart` | live map (flutter_map + OSM tiles, `userAgentPackageName` set per OSM policy), marker at `lastLocation`, 24 h trail polyline from `devices/{id}/locations`, follows new positions; battery icon coloured by level with "updated x ago"; Open in Maps |
| `lib/screens/cane_screen.dart` | cane status + people with Owner/Primary/Cane-user badges; owner/primary get add/remove/make-primary/link/rename via `/manage` |
| `lib/screens/alert_detail_screen.dart` | SOS screen: name/time/location/battery/status, "X is handling this", I'm on it, Open in Maps, Mark Resolved (caregivers only) |

## Android build specifics (already configured — don't undo)

- `compileSdk = 37` (flutter_local_notifications requirement).
- Core library desugaring enabled + `desugar_jdk_libs:2.1.5` dependency.
- Manifest: `POST_NOTIFICATIONS` permission and
  `firebase_messaging_installation_id_enabled=true` meta-data (required by
  firebase_messaging's `register()`/`onRegistered` token API).
- `android/gradle/wrapper/gradle-wrapper.properties` points at a LOCAL gradle
  zip — see [Dev environment](Dev-Environment.md).
- Firebase config: `lib/firebase_options.dart` + `google-services.json`,
  both generated by `flutterfire configure`.

## SOS alarm flow

1. Backend sends a **data-only**, high-priority push (`kind: sos`).
2. App killed/backgrounded → `firebaseBackgroundHandler` (main.dart, own
   isolate) → `SosAlarm.ring`. Foreground → `onMessage` → ring + open
   `AlarmScreen` directly.
3. The notification is on channel `sos_alarm` (or `sos_alarm_dnd` once DND
   access is granted — channels freeze their settings at creation, hence
   two). Full-screen intent: with the screen off/locked Android launches
   `MainActivity` straight into the alarm. `MainActivity` enables
   `showWhenLocked`/`turnScreenOn` only for launches with action
   `SELECT_NOTIFICATION` (not in the manifest — otherwise the app would be
   readable over the lock screen any time); `AlarmScreen` turns it off on
   close via `truepath/alarm` `setAlarmMode(false)`.
4. I'M ON IT (screen or notification action) → `SosAlarm.stop` locally →
   `/ack` → backend `stop` push → every other caregiver's alarm is replaced
   by "X acknowledged the SOS and is on it".
5. Pushes older than 30 min (phone was offline) never ring — plain note.

Gotcha (found in testing): Android **auto-groups** an app's notifications
once there are ~4 ungrouped ones and auto-grouped children are SILENT — the
alarm then neither rings nor launches full-screen. Every SOS notification
therefore carries its own `groupKey: truepath.sos.<alertId>`. Keep it.

Manifest permissions for this: `USE_FULL_SCREEN_INTENT`, `VIBRATE`,
`ACCESS_NOTIFICATION_POLICY`, `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`,
`WAKE_LOCK`. Old app versions (before the alarm) show NOTHING for data-only
pushes — everyone must update.

## Build & run

```bash
cd app
export JAVA_TOOL_OPTIONS=-Djava.net.preferIPv4Stack=true
flutter build apk --debug          # or: flutter run
```
VS Code: F5 ("TruePath Care (debug)") or the "app: build debug APK" task.
